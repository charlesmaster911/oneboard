# OneBoard 기존 자료 복원·실데이터 연동 설계

## 목표

기존 OneBoard의 팀 KPI, 운영매뉴얼, 설정 화면을 현재 인증 구조 위에 복원하고, 카페24·네이버 스마트스토어·쿠팡 한반도 매출과 META·네이버 검색광고 데이터를 실제 API에서 수집한다. 카카오 톡스토어·선물하기 매출은 공개 판매자 API가 없으므로 인증된 Google Drive CSV 수집 경로로 합친다.

## 사용자 경험

- 상단 메뉴는 `매출 / 팀 업무 / 회의록 / 팀 KPI / 운영매뉴얼 / 설정`으로 복원한다.
- 팀 KPI는 현재 업무 API를 기준으로 완료율, 지연, 중요 미완료, 담당자별 처리량을 계산한다.
- 운영매뉴얼은 기존 21개 문서를 로그인한 사용자만 검색·열람할 수 있게 한다.
- 설정은 owner 전용이며 플랫폼별 연결 상태, 마지막 갱신, 최근 동기화 결과, 연결정보 저장, 수동 갱신을 제공한다.
- 매출 화면은 숫자 `0`을 무조건 정상값처럼 표시하지 않는다. `실제 0 / 미연결 / 수집 실패 / 아직 수집되지 않음`을 구분한다.
- 실제 데이터의 출처와 마지막 갱신 시각을 항상 표시한다.

## 보안

- 매뉴얼 원문은 정적 사이트에 복사하지 않고 인증된 백엔드 API에서만 반환한다.
- 플랫폼 비밀값은 기존 암호화 저장소를 사용하며 화면에는 저장 여부와 계정 식별자 끝 4자리만 노출한다.
- owner 권한은 기존 Google 로그인 역할로 판정하고, 예전 localStorage 비밀번호는 복원하지 않는다.
- 오류 응답과 동기화 로그에는 토큰, 계정 비밀값, 원본 예외를 노출하지 않는다.

## 데이터 흐름

1. 09:00 KST 자동화가 판매 API와 광고 API를 수집한다.
2. 16:00 KST 자동화가 광고 API를 다시 수집한다.
3. Google Drive 수집기는 카카오 톡스토어·선물하기 CSV를 읽어 같은 `daily_metrics` 테이블에 넣는다.
4. 대시보드는 일별 집계와 플랫폼별 집계를 인증 API에서 조회한다.
5. 플랫폼 상태 API는 연결 여부, 최근 동기화 결과, 수집 건수, 완료 시각을 합쳐 반환한다.

## 플랫폼 범위

- 판매 공식 API: `cafe24`, `naver_store`, `coupang`
- 광고 공식 API: `meta`, `naver_ads`
- 선택 광고 API: `kakao` (카카오모먼트 연결정보가 있을 때)
- Drive 수집 판매: `kakao_talk_store`, `kakao_gift`

## 실패 처리

- 외부 API가 오류를 반환하면 빈 성공 배열로 바꾸지 않고 플랫폼 동기화를 실패 처리한다.
- API가 정상 응답했지만 데이터가 없는 경우에만 `recordsSynced: 0` 성공으로 기록한다.
- 한 플랫폼 실패는 다른 플랫폼 수집을 계속하되 전체 작업은 `partial_failure`로 기록한다.
- 설정 화면에서 사용자가 다음 조치를 알 수 있게 `연결정보 필요`, `권한/토큰 확인`, `정상·0건`, `수집 실패` 문구를 표시한다.

## 화면 방향

기존 OneBoard의 흰색 배경, 블루 포커스, 단단한 카드 구조를 유지한다. 이번 복원의 대표 요소는 모든 채널 카드에 붙는 상태 스트립이다. 초록은 실제 수집 완료, 노랑은 연결정보 필요, 빨강은 실패, 회색은 미수집을 뜻한다. 화려한 장식보다 운영자가 무엇을 해야 하는지 즉시 판단하는 밀도와 가독성을 우선한다.

## 완료 조건

- 프론트와 백엔드 전체 자동 테스트 및 프로덕션 빌드가 통과한다.
- 실제 배포 주소에서 로그인 후 여섯 메뉴가 보이고 권한에 맞게 동작한다.
- 운영매뉴얼 목록·검색·본문 열람이 가능하다.
- 팀 KPI가 실제 업무 데이터로 계산된다.
- 설정에서 플랫폼 상태와 동기화 상태가 보이고 owner가 연결정보를 저장할 수 있다.
- 수동 동기화가 요청되고 결과가 상태 화면에 나타난다.
- 데스크톱과 390px 모바일에서 열람·입력이 가능하다.
- 브라우저 콘솔의 OneBoard 원인 오류가 0건이다.
